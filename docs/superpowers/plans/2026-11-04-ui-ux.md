# Bikin CV v1.1 (UI/UX: rapikan + navigasi) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ganti shell aplikasi jadi 3 kolom dengan rail 10 langkah, accordion per section, progress/status, undo hapus, dan umpan balik simpan — tanpa mengubah lembar CV A4 maupun ekspor.

**Architecture:** `js/progress.js` (baru) adalah satu-satunya sumber aturan status/progress dan tidak menyentuh DOM. `form.js` merender tiap langkah sebagai `<details>` dan melaporkan aksi destruktif lewat callback; `main.js` memegang state UI (langkah aktif, section terbuka, undo pending) dan mengecat rail/progress/toast. `preview.js`, `docx.js`, `photo.js`, dan `css/cv.css` tidak disentuh.

**Tech Stack:** Vanilla ES modules, `<details>`/`<dialog>` native, CSS grid, `node:test` untuk unit, Puppeteer untuk E2E (dev-only).

**Spec:** `docs/superpowers/specs/2026-11-04-ui-ux-design.md`

## Global Constraints

- Situs tetap tanpa build step; semua JS ES module; CSP `default-src 'self'` (tidak ada inline `<script>`; inline `style` boleh).
- `css/cv.css`, `js/preview.js`, `js/docx.js`, `js/photo.js` **tidak boleh berubah**.
- Print wajib tetap 1 halaman A4 berisi teks asli; elemen UI baru `display:none` saat print.
- Draft tetap satu kunci `bikincv.draft.v1`; tidak ada field baru di state/JSON.
- Target sentuh ≥44px; kontras ≥4.5:1; tanpa `alert()`/`confirm()`.
- Tanpa request eksternal (font/ikon/gambar); ikon = inline SVG.
- Semua teks UI bahasa Indonesia, sapaan netral (bukan "gwe/lu").
- Kode & commit mengikuti gaya repo: komentar Indonesia, pesan commit `feat:`/`fix:`/`test:`/`docs:`.

## Review Focus

1. **Print saat semua section terlipat** — user melipat semua bagian lalu menekan Simpan PDF; PDF harus tetap memuat seluruh isian (preview terpisah dari form). Uji di Task 6.
2. **HP 390px dengan label/status panjang** — "Pengalaman Organisasi" + pill "Sebagian" tidak boleh mendorong toolbar/progress melewati 390px. Uji di Task 3.
3. **State kosong** — overlay pratinjau tampil saat lembar benar-benar kosong dan hilang begitu nama/kontak diisi, serta tidak ikut tercetak. Uji di Task 5.
4. **Import JSON v1** dengan urutan/hide dari template lain — nomor langkah, status, dan `aria-current` harus ikut `state.order` tanpa error. Uji di Task 4.
5. **Undo setelah hapus** — entri kembali di indeks semula dengan isi identik; undo batal bila user ganti template/import/hapus lagi. Uji di Task 5.

```js
export async function openApp(browser, url, { w = 1366, h = 900, mobile = false } = {}) {
  const page = await browser.newPage();
  await page.setViewport({ width: w, height: h, isMobile: mobile });
  const errors = [];
  page.on("pageerror", (e) => errors.push(e.message));
  page.on("console", (m) => m.type() === "error" && errors.push(m.text()));
  await page.goto(url, { waitUntil: "networkidle0" });
  await page.evaluate(() => localStorage.clear());
  await page.reload({ waitUntil: "networkidle0" });
  return { page, errors };
}
```

## Catatan pelaksanaan

- Task 3 mengubah `main.js` besar-besaran; Task 4 dan 5 menambah di atasnya. Jangan mengerjakan 3–5 secara paralel di file yang sama.
- Kalau `renderForm` perlu dipanggil ulang (ganti template/import), `activeId`/`openIds` harus dihitung ulang dari state baru sebelum render, dan `clearUndo()` dipanggil.
